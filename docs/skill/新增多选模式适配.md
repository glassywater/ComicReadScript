# 新增多选模式适配

## 前置判断：是否真的需要多选适配

多选加载是站点适配之上的**额外能力**，需要用户能自选要加载的内容时才需要新增多选适配，目前只有两种场景：

- **选择多个作品合并加载**：在列表页勾选多个作品，把所有作品的页按顺序合并成一本阅读（pixiv、kemono）
- **选择一个作品里的指定页**：在缩略图页勾选要加载的页，只加载这些页（ehentai）

多选适配**必须建立在已有站点适配之上**（页面已通过 `setup()` / `setupSiteAdapter()` 接入、且能在 handler 里拿到 `coreCtx`）。

## 两种模式

两种模式在实现上是同一套机制，区别只在于**可选项的粒度**：

| 模式           | 可选项粒度 | `getImgList` 返回值    | 参考实现                                                                                                           |
| -------------- | ---------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 多作品合并加载 | 一个作品   | 整本作品的所有页       | [src/site/pixiv.tsx](../../src/site/pixiv.tsx)、[src/site/kemono.tsx](../../src/site/kemono.tsx) 的 `list` handler |
| 单作品选页加载 | 一页       | 单页 `[{ src, name }]` | [src/site/ehentai/multiSelectLoad.tsx](../../src/site/ehentai/multiSelectLoad.tsx)                                 |

## 实现方式

核心是 [src/userscript/core/multiSelect/useMultiSelectLoad.tsx](../../src/userscript/core/multiSelect/useMultiSelectLoad.tsx) 导出的 `useMultiSelectLoad`（从 `core` 导入）。它把两种模式统一成同一个模型：**每个「可选项」有一个 id，站点提供 `getImgList(id)` 拿到该可选项的图片列表，确认加载后按选择顺序把所有列表合并成一条**。

站点只需要做 3 件事：

1. 调用 `useMultiSelectLoad(coreCtx, options)` 传入 `getImgList` 与 `registerItems`（遮罩会盖在注册的 DOM 上）
2. 提供 `isSameList` 标识同一列表的翻页（翻页时只卸载遮罩、保留选中状态，否则页面切换会完全销毁控制器）
3. 返回 `ms.createCleanup()` 作为页面清理函数

其余能力（FAB 多选按钮、快捷键、ESC 退出、选中状态缓存、懒加载合并）都由 `useMultiSelectLoad` 自动完成。`options` 的完整参数与 `ms` 控制器的方法见该文件中 `MultiSelectLoadOptions` / `MultiSelectLoadController` 的类型定义与 JSDoc，实现细节以代码为准。

## 注意事项

- 遮罩 `SelectionMask` 是绝对定位的，可选项 DOM 需要是定位元素（`position: relative`）：可用 `onStart` 设置（参考 kemono），或直接加 CSS（参考 ehentai）
- 是否传 `allItemIds` 决定 `v` 键的行为：传了（如 ehentai）则 `v` 直接进入阅读模式并默认加载全部页；不传（如 pixiv）则 `v` 会先走多选确认流程
- 合并顺序 = 选择顺序，遮罩上显示的序号即最终阅读器里的页顺序
- 图片按阅读进度懒加载合并，总页数随加载动态扩展（`getImgList` 会被按需多次调用）
- 选中状态按列表 id 自动缓存并恢复（未确认存 `pending`、确认后存 `confirmed`）
- 为站点新增多选支持后，需在 [src/index.ts](../../src/index.ts) 的站点注释链接后追加标记（`<sup>合订</sup>` 多作品合并 / `<sup>选页</sup>` 指定页），README 与 docs/index.md 的「支持网站」会在下次构建时由 doc-generator 自动生成对应上标；有专属章节的手动站点则在 README 手动区站名后加 `<sup>`
- 修改完成后运行 `pnpm check` 确保没有 ts、lint 错误
