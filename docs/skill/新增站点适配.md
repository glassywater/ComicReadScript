# 新增站点适配

## 前置判断：是否真的需要适配

大部分网站都可以直接用「**简易阅读模式**」支持，由 [src/userscript/otherSite](../../src/userscript/otherSite) 自动识别页面中的图片并进入阅读模式。

**只有以下情况才需要新增站点适配：**

- 「简易阅读模式」无法正确识别图片，或识别出的阅读体验太差
- 需要阅读模式以外的增强功能

## 判断适配方式

先判断用哪种方式适配，复杂程度递增：

1. **简单站点：直接写在 [src/index.ts](../../src/index.ts) 入口**。只要「能拿到图片列表 + 简单翻页」即可，在入口的 `switch (location.hostname)` 里加一个 `case`，用 `setup()` 适配，**无需新建文件**。如果图片全部显示在网页上（不需要请求接口或手动拼图片列表），可以直接用 `setupSimple()` 自动扫描页面图片。参考入口里 zaimanhua、manhuagui、komiic、hitomi 等 `setup()` 站点，以及 `klz9.com` 的 `setupSimple()` 写法。
2. **复杂站点：[src/site/](../../src/site/) 下新建模块**。页面是 SPA、需要 `getPageContext` / `handlers` 能力，或代码量大、需要拆成多个文件、叠加多项增强功能时，在 `src/site/` 下新建文件（如 `src/site/xxx.tsx`），内部用 `setupSiteAdapter()` 初始化，然后在 `src/index.ts` 的 `case` 里 `selfImport('site/xxx')` 加载。参考 [src/site/ehentai](../../src/site/ehentai)（多文件）、[src/site/pixiv.tsx](../../src/site/pixiv.tsx)（简单模块）的写法。

## 入口注册

在 `src/index.ts` 的 `switch (location.hostname)` 中增加站点对应的 `case`，并在 `case` 上方加两行注释。这两行注释会被构建时的 [doc-generator](../../scripts/lib/doc-generator.ts) 自动解析，用于更新 README.md 和 docs/index.md 中的支持站点列表：

```ts
// #站点分类[网站名](网站链接)
// test: https://...（测试用的指定章节链接）
case 'example.com': {
  // ...
}
```

- 第一行：`#` + 站点分类 + md 格式的网站链接和名字，如 `// #漫画站（中文）[再漫画](https://manhua.zaimanhua.com/)`。**分类必须复用现有分类**
- 第二行：测试用的指定章节链接，如 `// test: https://www.dm5.cn/m1033552/`；无法提供时写明原因（如 `// test: 有cf验证，跳过`）

## 编写站点代码

`setup()` / `setupSimple()` / `setupSiteAdapter()` 都从 `core` 模块导入，各字段以 [src/userscript/core/siteAdapter/setup.ts](../../src/userscript/core/siteAdapter/setup.ts) 的 `SetupOptions` 类型及其 JSDoc 为准（章节相关类型见 [src/userscript/core/types.ts](../../src/userscript/core/types.ts)），本文不复述。

其中 `onPrev` / `onNext` 的取舍：优先用准确获取按钮的方式（返回点击函数或 undefined）；无法稳定获取按钮时，改用直接跳转上/下话链接的方式；连链接也拿不到就放弃该功能。

### 章节模式（能拿到章节数据时优先使用）

只要站点有办法拿到章节列表的数据（页面上的目录 DOM、章节 API 等），就**优先使用章节模式**，而不是 `getImgList` + `onPrev`/`onNext`：用 `getChapterList` + `getCurrentId` + `getChapterImgList` 替代 `getImgList`（两者互斥，类型上已做联合约束），目录面板、上下章切换、下一章预取、地址栏同步等能力由章节管理器（[src/userscript/core/chapters](../../src/userscript/core/chapters)）自动接管，无需自行实现。

寻找章节列表数据的方法与下文「获取图片 url 列表的优先级」相同（全局变量 → 分析请求 → 现成方案）。

关键约束（详细机制见 chapters 模块的代码与注释）：

1. **`getChapterImgList` 必须能为任意章节加载图片**，不能依赖当前页面状态——预取会在读者还在看第 N 章时，就用第 N+1 章的 id 调用它
2. **`getCurrentId` 必须新鲜解析**（如从当前 URL），每次进入漫画页时求值，绝不能缓存
3. **章节列表的顺序就是阅读顺序**，站点 DOM 中的列表常是倒序（最新在前），需要 `reverse()`

完整章节数据往往比当前章节的图片更慢，可以先设置 `imgListMap['']` 让当前章节立即开始加载，拿到完整列表后再调 `setupChapters()`（从 `core` 导入）进入章节模式，已加载的图片会被无感转移。具体参考 [copymanga 的实现](../../src/site/copymanga/index.tsx)。

### setupSimple（图片全部显示在网页上）

如果目标页面的图片已经全部渲染在 DOM 中（包括懒加载后随滚动出现的图片），可以直接用 `setupSimple()` 自动扫描并收集图片，无需自己写 `getImgList`。用法与参数见 [setupSimple.ts](../../src/userscript/core/siteAdapter/setupSimple.ts) 的 `SimpleSetupOptions` 类型及其 JSDoc，参考 [src/index.ts](../../src/index.ts) 中 `klz9.com` 的写法。

参考：

- 简单站点：`setup()` / `setupSimple()` 用法见 [src/index.ts](../../src/index.ts) 内的各个 `case`
- 复杂站点：`setupSiteAdapter()` 用法见 [src/site/nhentai.tsx](../../src/site/nhentai.tsx)、[src/site/pixiv.tsx](../../src/site/pixiv.tsx)

## 获取图片 url 列表的优先级

按以下优先级依次尝试：

1. **通过网页的自定义全局变量直接获取**（最快）。在站点漫画页的网页控制台执行下列代码，找出网页内的自定义全局变量，手动检视能否直接拿到所有图片链接：

```js
const iframe = document.createElement('iframe', { url: 'about:blank' });
iframe.style.display = 'none';
document.body.appendChild(iframe);

Object.fromEntries(
  Object.entries(window).filter(([x]) => !Reflect.has(iframe.contentWindow, x)),
);
```

参考 [src/site/jm.tsx](../../src/site/jm.tsx) 的代码。

2. **通过分析网页源码或发起请求获取**。检查图片的 url、网页的源码，看网页本身是如何获取图片 url 的，可能需要发起请求（使用 `request`）。参考 [src/site/pixiv.tsx](../../src/site/pixiv.tsx) 的代码。

3. **搜索现成的适配方案**。以上都找不到时，优先搜索 [greasyfork](https://greasyfork.org)、[sleazyfork](https://sleazyfork.org) 上有没有该网站的脚本，其次是搜索 github 上的项目，最后才是在搜索引擎上搜索。

## 注意事项

- 复制其他站点的代码后，**一定要记得修改传给 `setup()` / `setupSimple()` / `setupSiteAdapter()` 的 `name` 字段**
- 修改完成后运行 `pnpm check` 确保没有 ts、lint 错误
